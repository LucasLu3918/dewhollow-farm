# DF-QA-008：寵物視覺基線穩定性

## 驗收方式

寵物截圖測試先等待場景內角色回到靜止姿勢，再呼叫開發模式限定的 `window.__dewhollow.pauseScene()`。hook 等待 Phaser `PAUSE` 事件確認暫停已生效，將玩家、可見 NPC 與夥伴 rig 擺回靜止 pose，再以固定 time 重繪天候粒子。此 hook 只在 `import.meta.env.DEV` 暴露，僅由 E2E 使用，不改正式版遊戲行為。

測試只涵蓋既有農場黑貓與村莊黑貓／矮袋鼠 canvas 基線；PNG 基線保持原樣。兩項測試使用 **1280×720** viewport，並在頁面載入前以 `addInitScript` 僅對 E2E 覆寫 MOBILE-007 的 desktop grid sizing，重建原 4:3 畫布幾何；測試斷言 canvas 為 **926×694**。首次 `Math.random()` 僅在這兩個測試中回傳 0，隨即還原原函式；`src/main.ts` 以此建立 seed 0，`advanceRng(0)=1013904223`，春季首日的 roll 為 24/100，落在晴天權重內。E2E 另斷言 HUD 顯示晴天。這不回退正式版 CSS，也不更動 production RNG；MOBILE-007 的響應式行為仍由其獨立測試覆蓋。

村莊進場後，測試等待 `cameraScroll()` 連續五個 animation frame 相同，pause 後再斷言相機位置未改變。兩張既有截圖測試各重複五次，共 **10/10 passed**，都符合原有 Playwright pixel threshold；沒有放寬門檻或更新 PNG。五張農場畫面 SHA-256 完全相同：`7157aa97d75998d3e4ff2c8fb4d0d624252ef2bf`。五張村莊畫面的檔案 SHA-256 不同，但都通過既有像素比對；這些差異未超出原有 matcher threshold。成功案例不產生 Playwright diff 圖，因此本次沒有可引用的最大像素差值。

## 限制

- 暫停的是 Phaser 場景更新；此方法不凍結瀏覽器本身、頁面外部計時器或網路服務。
- Playwright matcher 通過不代表 PNG bytes 相同；農場畫面 hash 穩定，村莊仍有低於原 threshold 的 raster 差異。此次未產生成功案例的 per-pixel diff，無法量化其最大差值。
- `npm run check`：typecheck 通過；Vitest **148 files passed, 1541 passed, 1 skipped**；production build 通過；首載 **2.761 MB / 8 MB**。
- `E2E_BASE_URL=http://127.0.0.1:5193 PWA_BASE_URL=http://127.0.0.1:4193 npm run test:e2e`：Chromium **177 passed**，2.5 分鐘。renderer canary 以 `test.fail()` 標記預期失敗，測試符合預期；測試使用隔離埠，未使用 4173/5173。
- 行動版尺寸與互動以 Chromium 模擬裝置驗證；沒有實體 iOS／Android 裝置測試。
- 沒有本次變更前同環境的 FPS、輸入延遲、場景載入或記憶體基準，因此不能判定這些指標的前後差異；E2E 的 30 秒效能面板測試只驗證取樣顯示，不能取代前後基準比較。
- 存檔載入／遷移、跨場景、農務與經濟狀態有單元及 E2E 覆蓋；未以額外外部舊版發行存檔做真實升級測試。
