# 實機效能量測

本文件說明怎麼在真正的手機上量測晨露農場的效能，對應 [ROADMAP](ROADMAP.md) M7 上線檢核表的未勾選項目：

> 效能：中階手機 ≥ 50 FPS；首次載入 ≤ 8 MB（不含延後載入的區域素材）

**桌面瀏覽器或節流模擬不能代替實機。** 模擬器與無頭瀏覽器沒有手機的 GPU、散熱與電池限制；本專案的桌面量測（60 FPS、CPU 節流 4 倍時遊戲程式幾乎不耗時）只說明「瓶頸不在遊戲邏輯」，不能判定手機能否達標。

## 1. 準備

### 1.1 選兩台裝置

- 一台 **iPhone**（Safari）與一台 **中階 Android**（Chrome）。選機時寫下型號與系統版本，之後每筆紀錄都要附上。
- 用平常的使用狀態：不要開著其他重度 App，電量高於 50%，**關閉低電量模式**（低電量模式會限制效能）。

### 1.2 要量測哪個網址

有兩種網址，建議兩種都量，並分開記錄：

| 網址 | 怎麼來的 | 用途 |
| --- | --- | --- |
| 區域網路（HTTP） | 在電腦上建置後，用預覽伺服器開放給同一個 Wi-Fi | 快速迭代；**沒有 Service Worker**（非安全來源），所以不含離線快取 |
| 正式網址（HTTPS） | 依 [DEPLOY.md](DEPLOY.md) 發布後的網址 | 玩家實際會遇到的情況，含 Service Worker 與 CDN |

區域網路的步驟：

```bash
npm run build
npx vite preview --host 0.0.0.0 --port 4173 --strictPort
```

在電腦上查出 Wi-Fi 的 IP：

```bash
ipconfig getifaddr en0
```

手機開啟 `http://<上面查到的 IP>:4173/?perf=1`。第一次執行時 macOS 防火牆可能會跳出詢問，要允許。

> 網址加上 `?perf=1` 才會顯示量測覆蓋層。沒有這個參數時，遊戲與平常完全一樣，覆蓋層不會佔用任何資源。

### 1.3 讀懂覆蓋層

覆蓋層在左上角，每半秒更新一次，分成兩個不同用途的視窗：

```
即時 5 秒視窗 FPS 58.7｜p50 16.9 ms｜p95 19.2 ms｜掉幀 2/298｜最慢 41.0 ms
完整 30 秒視窗：累積中（18 / 30 秒）
```

滿 30 秒有效前景時間後，第二列會顯示完整的 30 秒 FPS、p50、p95、掉幀數、最慢一幀與長任務數；切到背景超過一秒的間隔不會計入有效時間，也不會把當中的時間算成遊戲掉幀。短暫卡頓仍會保留。iOS Safari 不支援長任務紀錄時顯示「—」。

- **FPS**：由平均幀時間換算。這是玩家看到的畫面節奏（`requestAnimationFrame` 的間隔），不是 GPU 的耗時。第一列是 5 秒即時視窗，第二列是 30 秒量測視窗。
- **p50 / p95**：該列視窗幀時間的中位數與第 95 百分位。p95 大表示偶爾會卡，即使平均 FPS 漂亮。
- **掉幀**：該列視窗中超過約兩幀（33.4 毫秒）的幀數。
- **最慢**：該列視窗內最慢的一幀。
- **長任務**：第二列 30 秒內超過 50 毫秒的主執行緒工作。**iOS Safari 不支援此紀錄，會顯示「—」**，這是預期的，不是錯誤。
- 超過 1 秒的間隔會被忽略，避免切到背景後的空白時間拉低數字。

## 2. 量測情境

每個效能情境都從同一個存檔、同一個起點開始（建議用獨立的測試存檔）。流程：進入情境 → 等 10 秒讓覆蓋層穩定 → 持續執行情境操作 30 秒 → 記下第二列完整 30 秒視窗。不可只抄最後一次更新的 5 秒讀數。不同裝置各跑 3 次，記錄三筆數據並取中位數；若背景切換或通知中斷，重新開始該次量測。

| 代號 | 情境 | 操作 |
| --- | --- | --- |
| S1 | 農場靜止 | 在農場站著不動 |
| S2 | 農場連續走路 | 持續按住移動（觸控為按住方向鈕）在農場來回走 |
| S3 | 村莊（居民多） | 從農場走到村莊的門口，在村莊內走動 |
| S4 | 小屋（裝飾多） | 進入自家小屋，在裡面走動 |
| S5 | 重複使用工具 | 在農場重複開墾、澆水（觸控為點工具與動作） |
| S6 | 工具→種子→播種 | 從記錄好的存檔起點選鋤頭、選指定種子，在空田格播種；記錄操作次數、手勢數、完成秒數，並確認播種格與種子數量 |
| S7 | 旋轉與面板 | 從相同地圖位置開始，直橫式往返旋轉 10 次，開關一次主要面板；記錄操作次數、手勢數、完成秒數，確認人物、存檔狀態、面板內容與焦點 |
| S8 | 雨天／高密度田地 | 記下當次天氣與可見田格數；在相同區域重複使用工具，按 S1～S5 的完整 30 秒方法量測 |

每個操作情境的「操作次數」是有意觸發的按鈕或世界格點擊數；「手勢數」是連續 pointer 操作串數，例如一次搖桿拖動算一個手勢，不按底層 `pointermove` 數量計算。完成時間從第一個操作輸入到達成指定終態。S6～S8 是獨立操作基準；沒有可重現存檔時，記錄實際起點與終態，不填推測數字。若量測時下雨或下雪，把天氣和田格數記在備註裡。

## 3. 通過標準

來自 ROADMAP 的兩項：

- **FPS**：中階手機上，每個情境的 FPS 都要 ≥ 50。
- **建置預算**：`npm run budget` 以原始位元組檢查首次載入產物是否 ≤ 8 MB；gzip 數字只是補充。這不是網路傳輸量。
- **實際傳輸量**：另外記錄瀏覽器 Network 面板的 transferred bytes 與快取狀態。HTTP 本機預覽與 HTTPS 正式來源分開記錄；桌面參考值不能代替手機數據。

**建議的補充門檻（尚未正式採用，待你確認）**：每個情境的 p95 ≤ 33.4 毫秒（也就是 p95 不超過約兩幀），避免「平均很好但偶爾明顯卡頓」。

若某個情境未達標，先記錄完整讀數與裝置，再依下一節做剖析；不要憑感覺改程式。

## 5. 進階剖析（選用）

覆蓋層只告訴你「有沒有卡」，要找原因時再用標準開發者工具。選單名稱會隨瀏覽器版本改變，以下是大方向：

- **iPhone（需要一台 Mac）**：在 iPhone 的「設定 → Safari → 進階」開啟「網頁檢閱器」，用 USB 連到 Mac。Mac 的 Safari 會出現「開發」選單，選到你的 iPhone 與遊戲分頁後，用「時間軸」錄製，看畫面更新、JavaScript 與版面配置的時間佔比。
- **Android（需要一台電腦）**：在手機開啟「開發人員選項」與「USB 偵錯」，用 USB 連到電腦後，在電腦的 Chrome 開啟 `chrome://inspect`，選擇手機上的遊戲分頁，用「Performance」面板錄製。若要模擬低階裝置，可在面板中把 CPU 節流調到 4 倍（與本專案桌面量測的條件相同）。

使用開發者工具時，覆蓋層仍然開著，兩者的數字應該一致；不一致時以開發者工具的錄製為準，並把差異寫進備註。

## 6. 注意事項

- **溫度**：連續量測可能讓裝置升溫並改變效能。情境之間記錄溫度／發熱狀態，必要時休息到狀態穩定；不假設特定分鐘數必然降頻。
- **不要在充電時量測**：充電產生的熱會影響結果；量測時拔掉充電線。
- **背景 App 與通知**：量測前關掉其他 App，開啟勿擾模式，避免通知彈出中斷操作。
- **覆蓋層本身的成本很小**：它每半秒才改一次文字，每幀只做一次時間差的計算。
- **Service Worker**：區域網路的 HTTP 網址沒有 SW，所以「首次載入」與「離線」的數字只有正式網址才有意義。
- **偵錯時請關閉覆蓋層**：要比較正式體驗時，網址不要帶 `?perf=1`，因為覆蓋層本身仍然佔用一點 CPU。
