# 美術管線（風格鎖定、素材清單、本機產圖）

延續 [ART_STYLE.md](ART_STYLE.md)（目標風格與權利界線）與 [CHARACTERS.md](CHARACTERS.md)（角色文字設定）。本文件定義**怎麼把整套美術做得一致**。

## 1. 風格鎖定

整體風格採「明亮、飽和、Q 版、大頭小身、深色輪廓線、柔和高光與陰影，藍綠為主、粉色點綴」。待 [DECISIONS.md](DECISIONS.md) D2 確認解析度路線：

| 路線 | 說明 |
| --- | --- |
| A. 32 px 純像素 | 沿用現有格子大小；本機模型不產出真像素圖，縮小後易糊，後製量最大 |
| B. 64 px 手繪卡通（推薦） | 格子改 64 px；模型輸出縮小後直接可用，輪廓線與調色盤用後製統一 |

以下以路線 B 撰寫；若選 A，尺寸與張數估計依比例調整，流程不變。

**鎖定物**（先做、先核准、之後不再改）：

1. **風格樣張**：一張含角色、一格地形、兩件物件、一個 UI 元件的合成樣張，使用者核准後存入 `docs/art/style-sheet.png`。
2. **共用調色盤**：約 48 色（含 8 色膚色／陰影、季節四組地表色），存為 `content/palette.json`，所有素材最後都量化到此色盤。
3. **提示詞模板**：固定前綴（風格詞）＋固定後綴（負面詞），存為 `docs/art/prompt-template.md`；每張圖只換「主體」段。
4. **光源與輪廓**：光源固定在左上；輪廓 2 px 深棕（不用純黑）；陰影為橢圓落影。

## 2. 角色：以提供的圖片為原型

來源：使用者提供的角色原型圖（位置待確認，見 D1），畫面為兩位角色的真人風格插畫。處理原則：

- 原型圖**只作為私人參考**，不進 repo、不進 `public/`；遊戲內為 **Q 版重新設計**，不保留寫實臉部。
- 圖中的對話框、文字、背景、路人與任何非角色元素一律不使用。
- 角色特徵以 [CHARACTERS.md](CHARACTERS.md) 為準，並補上從原型圖讀出的細節（髮型輪廓、配件位置、表情），寫入 `docs/art/character-briefs.md`。

轉繪方式（D1 已決定採「圖生圖編輯模型」，並保留「看圖寫描述後文生圖」為備案）：

| 方式 | 作法 | 取捨 |
| --- | --- | --- |
| 看圖寫描述後文生圖（備案） | 由我讀圖，寫出精確角色描述，用 Z-Image Turbo（已實測、Apache-2.0）出 Q 版全身像，多 seed 挑選 | 最快最穩；像不像取決於描述，需人工挑選 |
| 圖生圖編輯模型（已選） | 把原型圖餵給 FLUX.2 klein 9B（已安裝，需先在 Hugging Face 接受授權，授權為 other）或 Qwen Image Edit（每步 316–450 秒） | 更貼近原型，但慢、未實測、授權需評估 |

**角色動畫的現實做法**：文生圖模型無法保證多幀一致，所以不要求模型畫完整動畫。

1. 模型產出每個角色的**四方向各一張標準站姿**（共 4 張）與必要表情頭像。
2. 行走：程式做 2 幀交替（上下起伏、左右微傾、腳部以預先切好的兩張「前腳」「後腳」疊圖，或在後製階段人工修兩張）。
3. 工具動作：揮動工具以**獨立工具精靈**在手部位置旋轉揮動，身體做壓縮拉伸，不重畫身體。
4. 站立呼吸、眨眼：程式縮放與疊圖。
5. 若品質不足，退到「人工修圖 2 幀」為第二方案；仍不足則由使用者決定是否外包繪製關鍵角色幀。

品質關卡：每個角色需在 1×、2×、4× 縮放下通過目視檢查（輪廓清楚、配色符合 CHARACTERS.md、四方向看起來是同一個人）。

## 4. 本機產圖流程（/local-image-model-router）

本機已安裝並實測可用：Z-Image Turbo（Apache-2.0、不需授權門檻、約 30 秒／768 px）。其餘模型多半未實測或授權為 other，需使用者同意才使用。

每件素材的流程：

1. **提示詞**：`風格前綴 + 單一主體 + 純色背景（洋紅 #ff00ff）+ 負面詞`。每張只描述一個主體；數量與位置交給程式，不寫在提示詞（本機已知：指定數量會出錯）。
2. **產圖**：同一模板、固定 seed 為基準，每件 2–3 個 seed 候選，一次只跑一個 MLX 任務；每張都寫入 `manifest.json`（模型、seed、提示詞、SHA-256）。
3. **去背**：模型沒有 alpha，改用**綠幕**（`#00ff00`，實際產出為淡綠）並以 `tools/art/key_out.py` 去背（背景色取自四角中位數、只移除與邊界相連的背景、壓掉綠色溢色）。環境：專案根目錄的 `.venv`（Pillow 11.3.0，版本記在 `tools/art/requirements.txt`），建立方式 `python3 -m venv .venv` 後 `.venv/bin/pip install -r tools/art/requirements.txt`。`tools/art/contact_sheet.py` 產生接觸表。洋紅背景實測會偏粉且帶深色落影，已不採用。
4. **縮放與統一**：`tools/art/finalize.py` 縮到畫格（輸出 `-2x` 母版與 1x 兩個尺寸）、外圍補一圈輪廓、量化到 `content/palette.json` 的 48 色（不抖色）並驗證輸出顏色都在調色盤內；落影由遊戲內另外畫橢圓，不烤進素材。實測 1x 的臉部細節會糊掉，建議引擎使用 `-2x` 並以 0.5 倍顯示。共用調色盤由 `tools/art/build_palette.py` 從已核准素材產生，格式有測試（`content/palette.spec.ts`）。
5. **審核**：用接觸表（contact sheet）看同組素材是否一致；不合格的重跑。
6. **入庫**：放入 `public/assets/<類別>/`，在 `content/assets.json` 補 `file` 與 `source`（寫明模型 id、seed、manifest 路徑）。
7. **驗證**：`npm run check`、`npm run test:e2e`；BootScene 載入失敗會顯示真實錯誤並退回占位圖。

產圖時間估計：550 件 × 平均 2.5 個候選 × 約 30 秒 ≈ 11 小時 GPU；以批次與最小可玩集優先，分多個工作階段在背景執行。

授權與來源：每件素材 `source` 需記錄模型與授權；發布前由使用者確認模型授權（Z-Image Turbo 為 Apache-2.0）。

## 5. 互動效果清單（M2）

| 情境 | 效果 |
| --- | --- |
| 走路 | 上下起伏、腳步塵土；草地有草葉飛起、泥地有塵、水邊有水花、雪地有腳印、木地板有小聲響 |
| 轉身 | 短暫壓縮拉伸 |
| 開墾 | 鋤頭揮動、土塊飛濺、田地由乾變翻土、鏡頭微震 |
| 澆水 | 水壺傾斜、水滴弧線、土色變深、小水花 |
| 播種 | 手部撒出種子、土面彈出小芽 |
| 收成 | 作物彈出、飛向背包圖示、閃光與飄字（數量、品質星） |
| 砍樹、挖礦 | 揮動、碎屑、震動、掉落物彈跳 |
| 釣魚 | 拋竿弧線、浮標漣漪、咬餌驚嘆號、拉竿水花 |
| 出貨 | 物品飛入箱子、箱蓋晃動、金幣音效 |
| 睡覺 | 淡出、星星飄過、隔日結算面板（出貨收入、成長、事件摘要） |
| 升級／成就 | 金色光環、角色舉手、彩帶、橫幅 |
| 表情氣泡 | 愛心、驚嘆、問號、汗滴、音符、睡眠 Z；頭上彈出 |
| 寵物 | 跟隨、偶爾打招呼、玩家站久會趴下；觸碰時冒愛心 |

## 6. 音訊（D5）

MVP 無音訊。上線前需要：動作音效約 40 個、音樂約 6 首（四季＋室內＋節慶）。來源待 D5 決定：程式合成音效與 CC0 素材包（登錄 `source` 與授權）。依 `audio-design` 技能建立音量匯流排（音樂、音效、環境、UI）與避讓（ducking）。
